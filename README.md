## Описание кейса

В рамках кейса необходимо разработать пользовательский блок для Puzzle RPA Studio, который автоматически извлекает реквизиты из PDF-документов с помощью Yandex Vision.

Блок должен принимать на вход путь к PDF-файлу, токен Yandex Cloud, идентификатор каталога, язык распознавания и формат вывода. После обработки документ отправляется в Yandex Vision, а результат возвращается в виде структурированного словаря Python или JSON-строки.

Основная задача блока — извлечь из PDF-документа ключевые реквизиты:

- тип документа;
- номер документа;
- дату;
- итоговую сумму;
- контрагентов;
- ИНН и КПП;
- табличные позиции: наименование, количество, цена и сумма.

Блок размещается в Puzzle RPA Studio в категории:

```text
Обработка документов → OCR
```

## Описание решения

`PDFYandexVisionBlock` — это расширение для Puzzle RPA Studio, которое добавляет готовый OCR-блок для обработки PDF-документов. Решение построено как переиспользуемый компонент: пользователь передаёт параметры в визуальном блоке, а вся логика распознавания, обращения к Yandex Vision, парсинга и обработки ошибок скрыта внутри расширения.

Решение не просто возвращает сырой OCR-текст, а преобразует результат распознавания в удобную структуру данных. Это позволяет использовать блок в реальных RPA-сценариях: например, для автоматического переноса реквизитов из счетов, актов, накладных и других документов в учетные системы, таблицы или внутренние сервисы.

## Архитектура

Проект разделён на несколько логических слоёв:

```text
Puzzle RPA block
        ↓
code.value.py
        ↓
process_pdf()
        ↓
Yandex Vision client
        ↓
OCR response
        ↓
parser
        ↓
normalizer
        ↓
dict / JSON result
```

### Puzzle RPA слой

Файлы:

```text
block.json
meta.json
values.xml
code.value.py
libs.py.json
typeToName.json
```

Этот слой отвечает за внешний вид блока в Puzzle RPA Studio, входные параметры, расположение в тулбоксе и вызов основной Python-функции.

### OCR слой

Файл:

```text
src/yandex_client.py
```

Этот слой отвечает за подготовку PDF-файла, формирование запроса к Yandex Vision, отправку документа на распознавание и получение результата.

### Parser слой

Файл:

```text
src/parser.py
```

Парсер анализирует распознанный текст и извлекает из него бизнес-сущности: номер документа, дату, сумму, ИНН, КПП, контрагентов и позиции документа.

### Normalizer слой

Файл:

```text
src/normalizer.py
```

Нормализатор приводит найденные значения к единому формату: даты — к стандартному виду, суммы — к числовому формату, ИНН и КПП — к очищенным строковым значениям.

### Error handling слой

Файл:

```text
src/errors.py
```

Слой обработки ошибок нужен для того, чтобы блок не ломал выполнение робота при типовых проблемах. Вместо необработанного traceback решение возвращает понятную структуру с кодом и описанием ошибки.

## Пайплайн работы блока

1. Пользователь добавляет блок **Распознать PDF (Yandex Vision)** в процесс Puzzle RPA.
2. В блок передаются параметры:
   - `TOKEN`;
   - `FOLDER_ID`;
   - `FILE_PATH`;
   - `LANGUAGE`;
   - `OUTPUT_FORMAT`.
3. Блок проверяет наличие обязательных параметров и доступность PDF-файла.
4. PDF-файл подготавливается и отправляется в Yandex Vision.
5. OCR-ответ преобразуется в текстовую и структурированную форму.
6. Парсер извлекает реквизиты документа.
7. Нормализатор приводит данные к единому формату.
8. Результат возвращается в формате `dict` или `json`.

## Параметры блока

| Параметр | Тип | Обязательный | Описание |
|---|---|---:|---|
| `TOKEN` | string | Да | Токен доступа к Yandex Cloud |
| `FOLDER_ID` | string | Да | ID каталога Yandex Cloud |
| `FILE_PATH` | string | Да | Путь к PDF-файлу |
| `LANGUAGE` | string | Нет | Язык распознавания: `ru`, `en`, `ru-en` |
| `OUTPUT_FORMAT` | string | Нет | Формат результата: `dict` или `json` |

## Формат результата

При успешной обработке блок возвращает структурированный результат:

```json
{
  "success": true,
  "document": {
    "type": "Счёт",
    "number": "ABC-123",
    "date": "2026-05-22",
    "total_amount": 25500.5
  },
  "counterparties": [
    {
      "name": "ООО «Ромашка»",
      "inn": "7701234567",
      "kpp": "770101001"
    }
  ],
  "items": [
    {
      "name": "Услуга разработки",
      "quantity": 2,
      "unit": "шт",
      "price": 10000.0,
      "amount": 20000.0
    }
  ],
  "warnings": []
}
```

При ошибке блок возвращает понятный ответ:

```json
{
  "success": false,
  "error": {
    "code": "FILE_NOT_FOUND",
    "message": "PDF-файл не найден",
    "details": "C:\\docs\\invoice.pdf"
  }
}
```

## Дополнительные преимущества решения

Помимо базового требования распознавать PDF через Yandex Vision, в решении предусмотрены дополнительные улучшения.

### 1. Структурированный результат вместо сырого текста

Блок возвращает не просто OCR-текст, а готовую структуру с реквизитами. Это упрощает дальнейшее использование результата в RPA-процессах.

### 2. Единый формат ошибок

Ошибки приводятся к единому формату `success: false`. Это удобно для обработки в Puzzle RPA: робот может не падать, а переходить по альтернативному сценарию.

### 3. Разделение логики по слоям

Код разделён на клиент Yandex Vision, парсер, нормализатор и обработку ошибок. Благодаря этому решение проще поддерживать, тестировать и дорабатывать.

### 4. Поддержка двух форматов вывода

Результат можно получить как Python `dict` или как JSON-строку. Это делает блок гибким для разных сценариев использования внутри Puzzle RPA.

### 5. Нормализация найденных данных

Решение не только находит значения, но и приводит их к более удобному виду: суммы становятся числами, даты приводятся к единому формату, реквизиты очищаются от лишних символов.

### 6. Offline-проверки для демонстрации

В проекте предусмотрены тестовые примеры и проверочные скрипты, которые позволяют проверить структуру результата без реального обращения к Yandex Vision. Это помогает быстрее готовиться к демонстрации и снижает риск ошибок на защите.

### 7. Безопасная работа с токенами

Токены и Folder ID не хранятся в коде. Они передаются только как входные параметры блока во время выполнения процесса.

## Установка

1. Распакуйте архив с решением.
2. Откройте Puzzle RPA Studio.
3. Перейдите в **Настройки → Расширения → Добавление**.
4. Укажите папку `PDFYandexVisionBlock`.
5. Перезапустите Puzzle RPA Studio.
6. Найдите блок в категории **Обработка документов → OCR**.

## Запуск

1. Добавьте блок **Распознать PDF (Yandex Vision)** на схему.
2. Передайте в него токен, Folder ID и путь к PDF-файлу.
3. Выберите язык распознавания и формат вывода.
4. Запустите процесс.
5. Используйте полученный результат в следующих шагах робота.

## Требования

- Windows 10/11
- Puzzle RPA Studio
- Python 3.11
- Доступ в интернет
- Аккаунт Yandex Cloud
- Установленные зависимости из `requirements.txt`

## Ограничения

- Для live-распознавания нужен доступ в интернет.
- Качество результата зависит от качества PDF или скана.
- Для плохих сканов возможны ошибки OCR, поэтому часть полей может вернуться как `null`.
- Токены и реальные документы не должны храниться в открытом виде в репозитории.

Решение представляет собой готовый пользовательский блок для Puzzle RPA Studio, который автоматизирует извлечение реквизитов из PDF-документов. Благодаря разделённой архитектуре, структурированному результату, обработке ошибок и поддержке offline-проверок блок можно использовать как основу для реальных RPA-сценариев документооборота.
