# DEMO_SCRIPT

Сценарий видеодемонстрации PDFYandexVisionBlock до 3 минут.

## Перед записью

- Подготовить PDF-документ для показа в Puzzle RPA.
- Подставить реальные `TOKEN` и `FOLDER_ID` только в параметры робота или безопасное окружение.
- Не показывать секреты на видео: скрыть поля, замазать значения или использовать экран без раскрытия токена.
- Проверить локальное parser demo:

```powershell
cd PDFYandexVisionBlock
python tools\run_parser_demo.py
python -X utf8 tools\validate_output.py examples\demo_result.json
```

Фактические пути для показа JSON:

- `PDFYandexVisionBlock/tools/run_parser_demo.py`
- `PDFYandexVisionBlock/examples/demo_result.json`

## Тайминг

### 0:00-0:20 - Блок в Puzzle RPA

Показать Puzzle RPA Studio и блок `PDFYandexVisionBlock` в категории `Обработка документов -> OCR`.

Сказать кратко:

> Это пользовательский блок для распознавания PDF через Yandex Vision и возврата реквизитов документа в dict или JSON.

### 0:20-0:50 - Входные параметры

Показать параметры блока:

- `TOKEN` - токен доступа к Yandex Cloud;
- `FOLDER_ID` - каталог Yandex Cloud;
- `FILE_PATH` - путь к PDF;
- `LANGUAGE` - язык распознавания;
- `OUTPUT_FORMAT` - `dict` или `json`.

Важно проговорить:

> Секреты не хранятся в коде и передаются только как параметры. На видео реальные значения не показываем.

### 0:50-1:30 - Запуск на PDF-документе

Показать запуск робота на подготовленном PDF-документе. Если сетевой доступ или токены недоступны во время записи, показать локальное parser demo:

```powershell
cd PDFYandexVisionBlock
python tools\run_parser_demo.py
```

Сказать:

> Локальное демо показывает расширенную структуризацию результата без обращения к Yandex Vision. Полный Puzzle RPA запуск использует тот же путь упаковки блока, но требует реальный PDF, токен и Folder ID.

### 1:30-2:10 - JSON-результат

Открыть `PDFYandexVisionBlock/examples/demo_result.json`.

Показать ключевые поля:

- `success`;
- `document.type`;
- `document.number`;
- `document.date`;
- `document.total_amount`;
- `counterparties`;
- `items`;
- `warnings`;
- `meta`.

Сказать:

> Результат структурирован и пригоден для дальнейших шагов RPA: проверки, маршрутизации, записи в учетную систему или выгрузки в файл.

### 2:10-2:40 - Обработка ошибки

Показать пример ошибки `success: false`, например неверный путь к PDF или пустой токен.

Сказать:

> Блок не роняет процесс traceback-ом. Он возвращает понятный код ошибки, сообщение и details, чтобы робот мог обработать ситуацию штатно.

### 2:40-3:00 - Преимущества

Коротко перечислить:

- переиспользуемый блок для Puzzle RPA;
- единый формат результата;
- понятные ошибки вместо падения процесса;
- локальное demo и validator для быстрой проверки;
- архитектура разделена на API-клиент, parser, normalizer и schema;
- секреты не хранятся в репозитории.

Финальная фраза:

> Решение можно развивать: заменить OCR-провайдера, улучшить парсер или изменить формат результата, не переписывая весь блок.
